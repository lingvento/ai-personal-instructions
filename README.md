# ChatGPT & Codex 个人指令

一套持续整理的中文个性化指令，覆盖 AI 怎样交流、判断信息、推进任务、控制行动范围和验证结果。

[ChatGPT 版](chatgpt/custom-instructions.md)侧重日常问答、学习、研究和产品讨论；[Codex 版](codex/AGENTS.md)在相同交流偏好上，增加任务授权、执行范围、子智能体、诊断与交付规则。

两份文件保留原作者实际使用的版本。默认读者是懂业务和产品判断、但不以写代码为主要工作的产品经理；其中很多约定也适用于研究、分析和日常协作。

## 直接使用

| 文件 | 使用位置 |
| --- | --- |
| [ChatGPT 个性化指令](chatgpt/custom-instructions.md) | 复制到 ChatGPT 的个性化设置中。 |
| [Codex 全局个人规则](codex/AGENTS.md) | 合并到 Codex 配置目录的全局 `AGENTS.md`。 |

**ChatGPT：** 在“设置 → 个性化”中编辑 ChatGPT 自定义指令。入口名称可能随版本变化，参见 [OpenAI 个性化说明](https://learn.chatgpt.com/docs/personalize)。

**Codex：** 默认全局文件是 `~/.codex/AGENTS.md`；设置了 `CODEX_HOME` 时使用该目录。已有规则先合并，项目命令和架构约定继续放在项目级文件中。参见 [OpenAI AGENTS.md 说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。仓库里的 `codex/AGENTS.md` 是模板，下载仓库本身不会将它安装为全局规则。

## 亮点与对应问题

下面从指令本身说明每组规则的用途；“针对的问题”是设计意图，不是已通过对照评测的效果承诺。

### 交流与判断

| 设计亮点 | 针对的问题 |
| --- | --- |
| **按目的安排信息量**：决策突出推荐和取舍，学习讲关键原理，完整交付按要求展开。 | 所有问题都写成长篇分析，或为了简短删掉必要解释；读者难以快速作决定。 |
| **伙伴式交流与独立判断**：平等讨论，允许有依据的不同意见；ChatGPT 版只纠正会影响结论或行动的前提。 | 说教、泛泛鼓励、无原则附和，或为了显得深刻而强行反驳和重构问题。 |
| **风险说明具体化**：风险、前提和不确定性仅在影响当前判断或行动时简短说明。 | 惯例性免责声明占据重点，真正需要注意的条件反而不清楚。 |
| **以业务理解解释技术**：按需要选择机制、流程、输入输出、取舍和边界，不机械覆盖全部维度。 | 非程序员收到大量代码、配置和术语，却无法判断技术对产品有什么影响。 |
| **澄清问题设门槛**：低风险、可逆的假设可以直接推进；信息会实质改变方向、结果或成本时才询问。 | 小细节不断打断任务，或者缺少关键条件时擅自猜测。 |
| **检索范围跟问题走**：ChatGPT 版不因提问语言局限于中文来源，中国本地信息优先中文原始来源。 | 中文提问只搜中文资料；研究全球技术时来源过窄，处理本地问题时又脱离实际。 |

### 行动与成本

| 设计亮点 | 针对的问题 |
| --- | --- |
| **讨论和执行分开授权**：Codex 版把解释、评审、诊断和方案设为只读；明确要求修改后完成改动与必要验证。 | 提个问题就被改了文件；已经授权的任务又因普通实现细节反复确认。 |
| **范围、成果和外部动作分别约束**：遵循已有结构，保护现有改动；扩大范围、重要接口变化、发布及难恢复操作有明确边界。 | 顺手重构无关内容、覆盖已有成果、擅自引入重要变化或执行外部动作。 |
| **按工作性质委派**：边界清晰、判断难度低且量大的工作可委派，规则确定的机械工作优先用程序。 | 强模型承担大量重复劳动；小任务也拆成多个 Agent；子智能体中间输出淹没主上下文。 |

子智能体规则同时限制上下文传递量、责任重叠和异常扩展，并要求主 Agent 整合与最终验证。这里指定 `gpt-5.6-luna` 和 `high` 推理强度，是原作者的模型配置选择，需按自己的可用模型调整。

### 诊断、证据与维护

| 设计亮点 | 针对的问题 |
| --- | --- |
| **根据复发情况选择修复位置**：单次问题可局部处理，重复问题检查共同输入、规则和流程。 | 只修当前样例，下一次又失败；或每个小问题都被升级为复杂的公共机制。 |
| **相关验证与如实交付**：检查目标行为，有合适样例时覆盖失败及正常或边界情况，说明未验证部分。 | 拿无关测试通过证明任务完成；通过弱化检查制造通过；把局部修复夸大为彻底解决。 |
| **区分事实、推断和未知**：变化中的事实核对权威一手来源，证据性表述提供可核验来源。 | 把猜测写成结论，把过时规范当作现状，或只说“研究表明”却不给出处。 |
| **按层级维护指令**：稳定偏好放全局，项目约定放项目文件，专项流程放 skill；优先删改合并。 | 单次问题不断变成永久禁令，全局文件越积越长，项目要求混入所有任务。 |

## 这套指令的取舍

它保留必要的判断空间：信息量由任务目的决定，澄清由影响决定，修复范围由复发概率、影响和成本决定。执行规则较具体的地方，是原作者希望稳定遵守的授权和成果保护边界。

因此，使用时更适合按自己的实际问题删改，而不是不断追加规则。尤其要检查这些个人选择：

- **角色与语言：** 默认中文、产品经理视角，可替换为自己的语言和技术熟悉程度。
- **授权边界：** Codex 版区分只读讨论、本地修改、外部动作和难恢复操作，使用前读一遍相关章节。
- **模型路由：** 指定的模型及推理强度不代表普遍适用的最低成本配置。
- **医学依据：** 两份文件都选择现代循证医学依据，不使用中医理论；这是原作者明确保留的领域偏好。

个性化指令表达协作偏好，实际效果仍取决于模型、工具环境和具体任务。
